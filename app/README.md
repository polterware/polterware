# Polterware GPUI Desktop

The Polterware Desktop in GPUI, on the shared library [polterware/ui](https://github.com/polterware/ui), and a client of the local Go core. It replaced the Electron Desktop, whose last source is the `polterware-old` checkout: where this README says "as Electron's", that app is the reference.

It finds the core that owns the database through `<db dir>/run/core.json` and reads it over Connect-JSON (`src/client.rs`: unary calls and server streams such as `ChangeService.WatchChanges`). It never opens SQLite. The messages and a client per service (`core.work().list_inbox(&request)`) are generated from `schemas/` into `src/contracts` by `tooling/gen-contracts`, which `bash tooling/generate.sh` runs; do not edit them by hand. The database is `POLTERWARE_DB`, else `~/Library/Application Support/polterware/local.db`. When no core runs, Start the core runs `polterware serve` detached, with the binary from `POLTERWARE_BIN`, the installed app, or this checkout's `dist/polterware`.

## Run

```bash
(cd backend && go build -o ../dist/polterware ./runtimes/cli)
cargo run -p polterware-gpui
```

Run from a build with no bundle, the app sets its Dock icon from `resources/polterware-icon.png` (`src/dock_icon.rs`), the Icon Composer export of `resources/polterware.icon` on the macOS icon grid; a bundle shows the compiled `polterware.icon`.

## Checks

```bash
cargo fmt --check
cargo clippy --all-targets
cargo test
POLTERWARE_TEST_BIN=../dist/polterware cargo test -p polterware-gpui --test live_core
```

`POLTERWARE_GPUI_SHOTS=<dir>` runs a tour that captures every screen to PNG and quits. Point `POLTERWARE_DB` at a scratch database to run it. `POLTERWARE_BENCH=<file>` makes the app append `projects-ready` when the Projects screen first shows rows.

## Package

```bash
bash tooling/release/bundle.sh                  # builds the core and the app
bash tooling/release/bundle.sh --existing-core  # takes dist/polterware as it is
```

It assembles `target/release-bundle/<version>/Polterware.app` (it stops if that folder exists): the name, bundle id, icon (`resources/polterware.icon`, compiled by `actool`), and the workspace version, the `polterware` core in `Contents/Resources` (where the app looks for it first), Sparkle in `Contents/Frameworks` with the feed and public key of `tooling/updater/sparkle.env`, ad-hoc signing, and the ZIP, DMG, and `SHA256SUMS` beside it. It never loads a signing certificate or Sparkle's private key. Inside the bundle, Sparkle checks daily and the app menu's Check for Updates… is enabled.

## What it has

- The frame: the title bar (Home, the breadcrumb, Commander, App settings), the project sidebar (Now: Inbox with its open count, Activity; Project: Milestones, Canvas, Structure, Knowledge; Project settings in the footer), and the inset main surface.
- The Projects screen, reached through Home, with every local project.
- The macOS menus as Electron's `application-menu.ts`: the app menu (About, Check for Updates…, Services, Hide, Hide Others, Show All, Quit), Edit, View (Toggle Full Screen), and Window (Minimize, Zoom).
- Commander (⌘K), as Electron's palette: the Navigation, Actions, and Recent groups with their icon tiles and shortcut or G-sequence hints (a remapped shortcut shows its new chord), the first row lit, and, while a card's page is open, Copy agent brief (`QueryPolter`) and Send this card to an agent first. Text that matches no command is a run: its Details, the Route, Milestone, Card, and Repository pills, and Start run (⌘Enter) start it through the Dispatch core (`DispatchService.StartRun`), and the run opens in Dispatch.
- Inbox (`WorkService.ListInbox`): items grouped by kind, open before Later, with the active item's detail, and Decide, Later, and Dismiss on one item or a selection (`ResolveInboxItem`).
- Activity (`AgentRunService.ListChanges`): the change history by day with the person, agent, and tier filters, merged with Polterware Dispatch's started, merged, and failed entries (`DispatchService.ListHistory`, through `<Dispatch data dir>/run/core.json`), and a change's or an entry's detail. A `dispatch://run/<id>` link, from an entry, a card's runs, or Commander's run, opens only when Dispatch is installed (a live `core.json` or a found binary), as Electron's `openInDispatch`.
- Knowledge: the Decisions, Rules, and Docs lists with their search and filters; the toolbar's "+" opening the shared Composer for a new decision or doc (`SaveKnowledge`) or Rule, and a Rule opened in it to edit or remove (Rules are written as Polter rule blocks through `WorkService.ApplyPolter`); the archived docs, each restored (`SetKnowledgeArchived`) or, once confirmed, deleted for good (`DeleteKnowledge`); and a decision's or a doc's page: the title and the Markdown body edited in place and saved as you type (`KnowledgeService.SaveKnowledge`), with the slash menu, the selection toolbar, code blocks with Copy, and the gutter's "+"; the Context as tokens, the tags, a decision's lifecycle moves and a doc's Archive, which ask why first, and the record's Activity. On a narrow window the page's rail is a drawer over the text.
- Milestones (`WorkService.ListMilestones`, `ListWorkCards`): the Roadmap, each milestone's stage progress and card count, reordered, renamed, or archived from its "…" menu (`UpdateMilestone`, `ReorderMilestones`, `ArchiveMilestone`); a board (All cards, a milestone, or the Backlog) as a Board, its cards dragged between stage columns, or as a List grouped by stage with selection, Move to stage, Move to milestone, and Archive; Peek on a selected row; a new milestone (`CreateMilestone`) or card in the shared Composer (cards are written as Polter blocks through `WorkService.ApplyPolter`), a move back or an archive asking why first; and a card's page: its intent, tasks (checked, reopened, or dropped), invariants, the next stage gate with its checks (`ReviewFeature`, `AdvanceFeature`), Verify (`VerifyFeature`), its commits (`LinkTaskCommit`, `UnlinkTaskCommit`), the last handoff, its Dispatch runs, the agent brief to preview or copy, and Activity; the rail's Stage, properties, questions, and Remove from board.
- Structure (`WorkService.ListStructure`, with the project's repositories, cards, records, Rules, platform connections, environments, and settings): the tree of the project's domains and components with its search and its Level and Kind filters, its pane hidden from the toolbar; and the selected node's document beside it: its level (switched between domain and component where it may), title, and summary edited in place (the project's own name and description through `SaveProject` and `SaveProjectSettings`); a component's Domain (a move), Kind and Technology tokens, Repository (a checkout or Choose folder…) and Folder, and Deploys, each opening the deploy Composer with its environment, platform, and target (`ListDeployTargets`), checked on its platform when the document opens and on demand (`CheckDeploys`); the Rules, cards, decisions, and docs that cite it, linked with "+" and unlinked with × (a card through its `under:`, a record through `SetScope`); and its Activity. Nodes are written as Polter blocks through `WorkService.ApplyPolter`. N, the tree's "+", and Commander's Add structure node open the node Composer; with no node yet, the page offers the agent prompts to copy.
- Canvas (`CanvasService.ListCanvases`, with the project's cards, decisions, Facts, and Structure nodes it can cite): the canvases as cards with their miniatures, a new one or Rename in the shared Composer (`CreateCanvas`, `UpdateCanvas`), Make agent-visible or Hide from agents, Archive, and the archived list to restore (`SetCanvasArchived`) or, once confirmed, delete for good (`DeleteCanvas`); and the editor (`GetCanvas`): the shape library with its search and the project's domains and components, clicked or dragged onto the dotted well; Select, Pan, and Connect; moving, resizing, nudging, and deleting the selection, a label edited in place, Undo and Redo, Arrange, zoom, and Fit; the inspector's Style, Text, Arrange, and Data for a shape (its family and type, fill and line, type, box, stacking, technology, description, project reference, and Promote to a card, decision, or Fact through `WorkService.ApplyPolter`), a connection's kind and label, and alignment for several shapes; every edit saved on its own half a second later (`UpdateCanvas`). Structure's Draw as canvas draws the tree on the project's Structure canvas, which Canvas then opens.
- The shared Composer over any page of a project, for a card (`ApplyPolter`, under a slug free across the project), a decision, or a doc (`SaveKnowledge`): C opens what the open tab creates on Milestones and Knowledge and a card elsewhere, and Commander's New card, New decision, and New doc and each page's "+" open it too.
- The scope filter: Domain and Component (and Environment on Activity and Docs) lead every page's filters in their own section, from the project's Structure nodes and environments; picking them on one page sets them for all, the Inbox, Activity's changes, Knowledge's records and Rules, and Milestones' cards being read under the picked nodes and the nodes below them (`scope_nodes`), and a new decision or doc starts with them as its Context. Opening another project clears it.
- The settings dialog over the page, from the sidebar's Project settings, the title bar's gear, ⌘,, and Commander, with one search across its tabs. The project's General (name and description through `SaveProject`, the default environment through `SaveProjectSettings`, and AGENTS.md sync through `SetAgentsSync`), Environments (`SaveEnvironment`, `DeleteEnvironment`), Platforms (the providers, their connections, imported resources, and sync runs; Connect signs in through the provider's CLI in a terminal session of the core and checks every 2 seconds until it is signed in), and Danger zone (Archive project, `ArchiveProject`). The app's MCP server (a helper `polterware mcp` this app starts and stops, and each client through `polterware setup mcp`), Agent setup, Hooks (`ProjectService.GetAgentSetup`, `SetHookSwitch`), AI skill, CLI reference (and its Markdown to copy), Shortcuts (each one remapped by pressing a chord), Appearance (Reduce transparency), Local core (status, Restart, Stop, the logs, idle timeout, auto start, and what quitting does), Privacy, and Danger zone (Reset local store).

The app's own choices live as JSON next to the database's default home, in `~/Library/Application Support/polterware` (`POLTERWARE_USER_DATA` moves them), in the files the Electron Desktop wrote, so its choices carry over: `core-preferences.json`, `quit-preferences.json`, `appearance-preferences.json`, and `shortcut-preferences.json`. When the core is not running at launch and auto start is on, the app starts it once.

The rest, in the order worth porting, is in [docs/future.md](../docs/future.md#gpui-desktop).
