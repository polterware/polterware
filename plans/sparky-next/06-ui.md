## State and data access in the renderer

- `window.sparky` (preload) exposes typed namespaces mirroring the RPC services (`memories`, `minds`, `tags`, `schedule`,
  `places`, `attachments`, `focus`, `review`, `search`, `reminders`, `activity`, `settings`, `agents`, `maintenance`, `app`)
  plus `onChange(cb)` (change stream) and `app.openDeepLink`, `app.pickFiles`, `app.revealInFinder`, `app.startMicrophone`.
- Query layer: small store per feature on `@polterware/frontend-state` (zustand) or Solid stores — **one cache keyed by
  entity type/id**, invalidated by `onChange`. Optimistic updates for toggles (done, pin, checklist) with rollback on error.
- Never block on the network of the world; the app is fully functional offline.

## Motion

Use the existing springs/tokens (`spring.fast|moderate|slow`, `--ease-*`, `--duration-*`). Required behaviors: DetailPanel
open/close per DESIGN.md; list item complete (check morph + fade of strike-through, 160 ms); calendar view switch (fade +
8 px shift, interruptible); focus ring progress (transform-only); reduced motion honored everywhere. Opacity may only animate in
the sanctioned shared presence primitives (DESIGN.md "Execution honesty").
